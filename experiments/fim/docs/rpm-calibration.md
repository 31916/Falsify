# RPM加算値の境界を調べる準備実験

## 目的と固定条件

FIMの出力RPMに対する正のOffsetだけを扱います。加算値の対象範囲は+500～+1500 rpm。
初回の10故障プロファイルは変更せず、別の設定・コード・結果として保存します。
STLは従来どおりRPM 599～6001、gear 0.5～4.5の範囲、時間0～30秒、故障開始5秒です。
故障は観測枝にあり、固定入力の下では内部のエンジン状態・速度・gearは変えません。

FalsifyのRAND/ACER/A3C/DDQNとΨ-TaLiRoは呼び出しません。
MATLAB/Simulinkに事前に決めた入力を与えて直接シミュレーションします。

## 入力と選定規則

設定の入口は [`config/rpm_calibration.json`](../config/rpm_calibration.json) です。

1. 初回実験の固定12入力を、保存されたB00波形の入力値からそのまま読み込みます。
   この12本には初回に固定seedで生成した4本も含まれますが、新しく乱数探索はしません。
2. 設定ファイルに宣言した一定入力40本、アクセル段階変化48本、ブレーキ段階変化24本を追加します。
   初回入力と完全一致する5本を除き、合計119本の異なる入力になります。
3. 全入力で正常モデルを実行し、5秒以降の最大RPMをMとして、加算値の境界6001−Mを求めます。
4. 暫定推奨値は、全固定入力中の最初の境界から1 rpm以上離れた、最小の5 rpm刻みの値です。
   ただし500～1500の範囲内に限定します。これは「反例を残す小さい故障」という規則であり、
   学習手法の優位性が最大になる値を探索する規則ではありません。

## 検証

- 初回12入力の正常波形が保存済み波形と一致することを確認します。
- 推奨加算値では全119入力を実際のFIM Offsetブロックに通して再実行します。
- 初回12入力では+500と+1500も再実行します。
- 初回入力の対象範囲内の境界、および追加入力を含む最初の境界について、境界−1、境界、境界＋1 rpmを確認します。
- 故障OFF、開始前の一致、故障ブロック前後の差、速度・gearが変化しないことを確認します。
- 独立のdp_taliroと解析式を照合し、Pythonで全保存波形を再監査します。

1 rpm刻みの全加算値の集計曲線は、正常波形を用いた解析計算です。
全曲線の各点を実シミュレーションしたとは扱いません。実行した組合せはvalidation.csvに記録します。
等号付近は境界として扱い、ρ<−1e−9だけを違反とします。

## 実行

```matlab
addpath('experiments/fim'); setup_fim();
calibrationRun = run_fim_rpm_calibration(previousRun, preparedRun);
```

- `previousRun`: 初回実験1のB00_U01～U12.matを含むrun。
- `preparedRun`: 現行の`run_fim_at_experiments('prepare')`で生成したrun。
- 新しいcheckoutでは、先にprepareとexp1を実行して比較元の固定12入力を再生成できます。
  過去の結果とのバイト単位の同一性を保証する意味ではありません。

```sh
.venv-falsify/bin/python experiments/fim/tests/test_rpm_calibration.py
.venv-falsify/bin/python experiments/fim/python/audit_rpm_calibration.py /path/to/calibration-run
```

結果は`results/fim/calibration/<一意ID>/`に保存します。
`RESULTS.md`と`reviewed_results.json`は監査に合格した後にPythonが作成します。
条件・入力・コードスナップショット・全波形・注入ブロックの前後ログを残します。

## 解釈上の制限

全入力が調整用です。追加入力を「独立した最終評価セット」と呼びません。
違反数/入力数はこの決め打ち集合での割合で、ランダム入力の違反確率ではありません。
調整後の比較実験には新しいseed・入力を使い、十分な探索予算を設定してください。
有限の入力・記録時刻列に対する確認で、全入力や連続時間の形式的安全証明ではありません。
